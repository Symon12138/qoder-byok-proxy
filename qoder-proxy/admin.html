维护说明

          
回滚会把 bundle 还原成官方版本，清空 BYOK 记录，摘掉代理，并重开自动更新。回滚后需：关自动更新 → IDE 走代理 → 应用全部补丁 → 重启 Qoder IDE。

        

      

    

  


  
  

    

      
常见问题 · 注意事项

      

        

          
Qoder 更新会冲掉补丁吗

          
会。Qoder 更新覆盖 bundle，补丁全部还原，.bak-* 备份也会被清掉。表现：模型名不对 / 专家团选不到自定义模型 / RepoWiki 又提示「无法生成」。修复：到「维护」点应用全部补丁，或跑 experts-patch.js --quest，然后重启 Qoder。

        

        

          
关闭自动更新为什么没用

          
Qoder 每次启动都会把 app.configAdvancedAutoUpdate 重置为 true，这是 Qoder 的自我保护，设置关不掉。真正的防线是发现症状后重打补丁。

        

        

          
同一时刻只能有一个模型在线

          
Qoder 的模型记录里只有一条自定义模型（默认 model_mocktest），所以同一时刻只有一个自定义模型在 IDE 里生效。控制台里可以存多套上游配置，但切换时会覆盖这条记录。

        

        

          
工具补全

          
你的模型不支持原生工具调用（tool_calls）时，代理会注入 Write/Bash/DeleteFile 等 5 个工具的系统提示，让模型用纯文本调用工具。已在 MiniMax/GLM/MiMo 上验证。

        

        

          
退出服务后 Qoder 还能正常用吗

          
能。退出服务会完整恢复官方状态：先清空 BYOK 模型记录、把各场景模型切回官方值，再去掉 http.proxy，最后才停本地代理并关闭控制台。下次要用第三方模型，重启控制台后点「走代理」即可。

        

        

          
「全部回滚」之后要做什么

          
回滚会重开自动更新。所以顺序是：关自动更新 → IDE 走代理 → 应用全部补丁 → 重启 Qoder IDE。

        

        

          
上游排队（queue.full / queue.waiting）

          
这是网关侧排队，不是故障。等一会儿自动放行，或在「上游详情」里换一个模型（不同模型队列独立）。

        

        

          
llm_return_empty 是什么

          
上游返回 JSON 错误、没有 SSE data: 行时，Qoder 会显示 llm_return_empty，完全看不出原因。代理已按四类映射（auth_error / rate_limited / content_policy_rejected / upstream_transient_error）。

        

        

          
数字显示异常

          
MiniMax 2.5 有时把工具返回的 JSON 数字切成科学计数法。上游模型行为问题，我们把值原样转发，不做改写。

        

        

          
进程为什么有时退出

          
曾观察到管理/代理进程偶发退出（原因未明）。遇到界面连不上时，重新点「IDE 走代理」即可拉起。

        

        

          
网关模型能力不准怎么办

          
保存上游时会自动同步模型记录（显示名、上下文、VL、思考等级）。若网关上报不准，可在「上游详情」的上下文长度里手动填，它会覆盖记录里的 max_input_tokens。模型记录只有 ID + 显示名 + 能力位三样，不要加别的字段，Qoder 会拒收。
